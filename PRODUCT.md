# Product

## Register

product

## Users

Molecular biologists designing oligos and primers from multiple sequence alignments. They work in long, focused sessions on a desktop (pywebview) or local web app: paste a sequence, run BLAST, align with MAFFT, pick a conserved region, design MOLigos and flanking primers, check thermodynamic QC, export a report. They are expert, iterative, and precise; they compare numbers across engines and notices mismatches. Primary UI language is English with Czech onboarding/What's New copy.

## Product Purpose

Oligool turns a query sequence into verified primer designs: fetch homologs (NCBI/Ensembl), align, design internal MOLigo splint oligos and flanking PCR primers, and QC them thermodynamically (IDT OligoAnalyzer and local Strider). Success is a correct pick fast, with every number traceable to the model that produced it, so the bench scientist trusts the result enough to order it.

## Brand Personality

Precise, calm, scientific. A lab instrument, not a web app: IBM Plex typography, zinc neutrals, one restrained teal accent, flat panels, no decoration that doesn't carry information.

## Anti-references

SaaS-marketing gloss. No gradient heroes, glassmorphism, buzzword copy, startup polish, or landing-page theatrics anywhere in the product. This is a workbench; every pixel earns its place by serving the task.

## Design Principles

- Numbers first, chrome second: thermodynamic values, sequences, and coordinates dominate; the interface gets out of the way.
- One vocabulary everywhere: one button system, one control shape, one panel language across every surface (shared tokens, no one-off variants).
- Say exactly what the model did: every computed value carries provenance (engine, parameter set, source: IDT or local); no unlabeled magic numbers.
- Pinned context, scrolling data: primary controls stay attached and visible while long alignments and results scroll beneath them.
- Restrained restraint: zinc + teal, motion only to convey state, density welcomed when it serves comparison.

## Accessibility & Inclusion

WCAG AA in both themes: body text >= 4.5:1 contrast; focus-visible rings on every interactive control; reduced-motion alternatives for any animation; dark/light parity as first-class, not an afterthought.
